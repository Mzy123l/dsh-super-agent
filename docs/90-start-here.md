## 2. 关于"填地址就集群"——我按你的思路做了，但加了一层

你的形状是对的：**一个字段决定拓扑，服务端只多一个"开始监听"的开关。**

我在上面补了三件事，理由如下：

| 补充 | 为什么必须 |
| --- | --- |
| **三方都是出站连接**（控制面也连 relay） | 你说"中心服务器可以向下 relay"。我把它推到极致：控制面也不监听公网。这样**控制面可以在 NAT 后面**，部署成本再降一档 |

relay的意思是，在中心服务器资源不足时（例如内存外存），可以指派其中一个PC，作为中心调度者的资源来源

| **哑中继 + 端到端加密** | 这两件事互为因果：因为加密，relay 解不开 payload；因为解不开，它**不可能**做智能调度，所以"哑"不是选择是必然。副产品是 relay 可以放在第三方、便宜的机器上 |
| **设备三态（含 degraded）** | 你说"连接时上报设备状态"。但如果 relay 是共享的，一次网络抖动会让**所有**设备同时掉线。所以必须有中间态：连接断 ≠ 任务停 |

另外我加了一个**检验标准**，写在 55 章开头：

> 集群化**不需要修改**领域模型与文件模型。如果集群要求改动它们，说明抽象错了。

这条标准让"单机先做"不是妥协，而是**验证抽象是否正确的手段**。

## 4. 我认为最有风险的三处

不是"没做完"，是**做完了也可能不对**。

### 风险一：D17「读时不管一致性」可能是错的

你的判断是"模型看到一半的文件会自己去找日志的"。我照写了，但这是**把一致性责任推给模型**。

问题在于：模型**不知道自己该去找日志**。它读到一份文件，默认假设它是完整且当前的。日志提供了发现渠道，但没有提供**提示**。

我保留了这个选择，但给出了升级路径（R6：拷进私有目录，接口不变）。**建议**：先按 D17 做，但在日志里加一条显式提示——"你在 seq N 读过的文件已在 seq M 被修改"。这样模型不需要"想起来去查"，而是被通知。

告诉模型日志记录，他会自己去找

### 风险二：强制 git 对"非代码目录"可能很别扭

你拍板"不管有没有都强制建 git"。技术上可行（[50-file-model.md](50-file-model.md) §5 有三套方案），但成本是真实的：

| 场景 | 代价 |
| --- | --- |
| 10GB 视频目录 | `git status` 要扫很久；必须靠 .gitignore 才可用 |
| 频繁变动的目录（下载文件夹） | 每次提交都很大 |
| 已经是 git 且**有未提交改动** | 必须用 `git stash create`，否则 Agent 看不到用户在写什么 |

第三条是最容易出事的。我在 50 章 §5.2 写了处理方式，但**这条会在真实使用中反复咬人**。

不再强制git

### 风险三：Watchdog 的 `stalled()` 谓词没有任何实测支撑

我定的判据是四个条件同时成立（工件无变化时间 + 工件变化数 + 回合数 + 重复度）。阈值是凭直觉给的。

这是整个设计里**唯一一个"我不知道它对不对"的地方**。所以我在 80 章 §5.3 坚持要**先建误报回放集再调参**——没有标注数据，调参就是盲调，而盲调的 Watchdog 会变成新的噪音源，比不做更糟。
