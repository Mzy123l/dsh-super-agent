# 文件模型

> 定稿依据：[40-decisions.md](40-decisions.md) 的 D7–D17。本章描述**单个节点内**的文件读写模型。
> 集群形态见 [55-cluster.md](55-cluster.md)，但文件模型的接口在所有拓扑下不变。

## 1. 三个区域

| 区域 | 谁可写 | 谁可读 | 隔离手段 |
| --- | --- | --- | --- |
| **私有目录**（每个 worker 一份） | 该 worker | 该 worker + host | dsh `workspace-write` |
| **公共区域**（托管根） | 只有文件调度者 | 所有人（经调度者发租约） | 版本化 CAS |
| **外部路径**（工作区之外） | 只有文件调度者，且必须预声明 | 经调度者 | 白名单 + 人审| 这个根据dsh的配置“在工作区内修改”“完全权限”“仅读取”自动适配读，写也一样，只不过多了文件调度者

```
workspace/
├── tickets/
│   └── <ticket-id>/            ← 私有目录，该 worker 的 workspace-write 根
│       ├── .git                ← 该 Ticket 独立仓库（D9）
│       └── …                   ← worker 自由读写
├── shared/                     ← 公共区域，托管根
│   ├── inputs/                 ← 只读参考（数据集、配置、文档）
│   ├── outputs/                ← 可写交付物（经调度者发布）
│   └── .current -> v000012/    ← 指针文件，实现整组原子切换
└── external/                   ← 外部路径的落点（预声明后才有）
```

### 为什么私有目录要有自己的 `.git`

不是为了版本控制（那是公共区域的事），是为了三件在**崩溃恢复、审计、防糊弄**上都必需的东西：

1. **可重建的真源**：崩溃后靠 `git status` 判断「命令是否已生效」；
2. **审计粒度**：Ticket 结束时能给出「到底改了哪些」，包括未提交的改动；
3. **回滚**：`git reset --hard <checkpoint>` 比「凭记忆撤销」可靠。

**注意**：这是**强制**的，不管原目录有没有 git（D9）。原目录是 git 仓库时，做法是从它建 worktree（共享对象库）；不是时，在侧车区建一个新仓库（见 §5）。
不强制，但建议

## 2. 私有目录的隔离：用 dsh 现成机制

隔离手段是 dsh 的 `workspace-write` 沙箱模式，把该 worker 的 workspace 根设为它的私有目录。

**必须诚实说明这个模式的口径**（官方文档原文）：

| 事实 | 说明 |
| --- | --- |
| 它限制的是**变更操作** | `read-only` 拒绝变更；`workspace-write` 把变更限于工作区根 + 临时目录 |
| 读「直接通过」 | 所以「读工作区内所有文件继承会话权限」= 读不做额外限制（D15） |
| 执行完整度分 `full` / `partial` | **Windows ACL 档是当前已知的 partial 情形** |
| 官方建议 | 「需要绝对边界的消费方可以拒绝或向上暴露它们」 |

因此本设计的定性是：**私有目录的隔离是默认值，不是安全边界。** 这与官方原型对命令垫片的定性完全一致。

> 如果部署要求强隔离，只有两条路：只在 Linux/macOS 部署，或给 Agent 配独立 OS 账号。这是操作系统层面的事，插件管不了。
官方办不到我们也办不到

### 一个必须堵的洞

`dsh-fs` 的 `processPathFromHostPath(hostPath)` 会把**绝对宿主路径映射进执行世界**（当后端共享宿主文件时）。如果我们希望「工作区之外只能经调度者访问」，就必须在自己的 provider 里显式让这个方法返回 `undefined`。

**不堵这个洞，「公共区域只有一个入口」这句话就不成立。**
官方办不到我们也办不到
## 3. 公共区域：版本化 CAS

### 3.1 版本号的定义（D16）

**只要发送修改请求就算新版本。** 版本号由文件调度者分配，单调递增，worker 不可自报。

```
version : uint64   // 调度者维护的单调计数
```

不用内容哈希的理由：大文件每次写都要全量哈希；而「同内容重写被误判为冲突」这种损失极小——冲突是真的冲突，重试一次即可。

### 3.2 写 = CAS

```ts
/** 公共区域的唯一写入口。版本必须匹配，否则拒绝。 */
interface SharedWrite {
  path: string
  content: Uint8Array
  expectedVersion: number      // 必填，不接受 undefined
  base?: string                // 可选：声明这份内容基于哪个版本，用于日志
}

type WriteResult =
  | { ok: true; version: number }
  | { ok: false; reason: 'stale'; actualVersion: number }
  | { ok: false; reason: 'denied'; by: PolicyReason }
```

**这等价于把 `ctx.fs` 的可选 `guard` 变成必填**（D13）。不引入新协议，只是把契约收紧。

而它顺带解决了「追加不能安全重放」的老问题：**带版本号的写天然幂等**——重放时版本不匹配就拒，不会重复追加。

### 3.3 整组原子：托管根用指针切换

一个请求覆盖 N 个文件时，只有托管根能保证整组原子：

```
写：.staging/<txid>/ 下写完所有文件 → 生成新版本目录 v000013/
    → 原子更新 .current 指向 v000013/      ← 这一步是原子的
    → 老读者仍引用 v000012/，不受影响
    → 无人引用 v000012/ 时回收
```

**外部路径做不到这一点**，见 §4。

### 3.4 1 写多读 = MVCC，不是读写锁（D12） √，按这个为准

读写锁有两个老问题：写者挨饿、多文件写入时读者看到改了一半的树。用版本切换就没有这两个问题：

| | 读写锁 | 版本切换（MVCC） |
| --- | --- | --- |
| 读者被写阻塞 | 是 | 否（读旧版本） |
| 写者被读阻塞 | 是（或挨饿） | 否 |
| 读者看到半成品 | 可能 | 否（版本是一致快照） |
| 代价 | 无 | 短暂双份磁盘占用 |

**「1 写 + 多读」从互斥问题变成了版本问题。** 只有「切换指针」那一瞬间是串行的。

### 3.5 读（D17）

读**不做一致性保证**。模型读到一半的文件时，可以通过只追加日志发现「这个文件在我读之后被改过」，自行决定重读。

这里接受一个残留风险：**模型可能没注意到**。之所以接受，是因为：

- 做一致性读要引入快照或读锁，成本比收益大；
- 真正的保护来自版本号（写的时候必定暴露冲突）；
- 日志提供了发现渠道，而不是完全无感。

**如果实践中发现这个风险太大**，升到 R6（拷进私有目录）即可，接口不变。

## 4. 外部路径：只保证单文件原子

「公共区域可能在**工作区之外**，也可能比工作区还小」（你在讨论中指出的）。这类目标：

| | 托管根 | 外部路径 |
| --- | --- | --- |
| 例子 | `shared/`、工作区子目录 | `/etc/hosts`、`~/.gitconfig`、共享盘 |
| 整组原子 | 可以（指针切换） | **不可以** |
| 单文件原子 | 可以 | 可以（临时文件 + 原子 rename） |
| 回滚 | 指针切回，瞬时 | 按日志逆序还原 |
| 失败处理 | 干净 | 可能留下半应用，**必须交人** |

**外部路径必须预声明**（部署时的 target set），不能运行时请求。否则一条提示词注入就能让 Agent 写任意文件——这是长文 §8.4「云端被攻破 → 所有端侧设备」的本地版。

```yaml
# 部署配置：外部可写目标，必须显式列出
externalTargets:
  - path: ~/.gitconfig
    mode: cas               # 带版本号写
    requireHuman: true      # 每次都要人确认
  - path: /data/exports/
    mode: append-only       # 只允许追加
    requireHuman: false
```

## 5. 强制 git 的落地细节 ❌不再强制git

### 5.1 三种原目录状态

| 原目录状态 | 做法 | 注意 |
| --- | --- | --- |
| **已是 git 仓库** | 直接用，从它 `worktree add` | 共享对象库，省磁盘 |
| **在某个仓库的子目录里** | 用仓库根建 worktree，Ticket 工作路径是子目录 | 路径映射要正确 |
| **不是 git 仓库** | 侧车区 `git init` + 首提交，再 `worktree add` | 需要 .gitignore 策略 |

### 5.2 有未提交改动时必须处理

**这是最容易出事的点**：`git worktree add <path> HEAD` 得到的是干净的 HEAD，**Agent 看不到用户正在写的东西**。这不是「少一点上下文」，是直接改错文件。

三种处理：

| 做法 | 保住改动 | 动用户工作区 |
| --- | --- | --- |
| `git stash create` 生成临时提交作为基线 | 是 | 否 |
| `git stash push` 真 stash | 是 | **是** |
| 直接快照工作区（复制） | 是 | 否 |

**推荐第一种**：`git stash create` 只产出提交对象，不改工作区，最安全。

### 5.3 `git init` 必须显式配置

```bash
git init -b main
git config core.autocrlf false
git config core.safecrlf false
git config gc.auto 0          # 关键：自动 gc 会抢 .git 的锁
```

最后一条尤其重要：**自动 gc 会在并发写的时候抢 `.git` 的锁**。关掉它，由我们自己决定何时 gc（在一个明确的静默窗口）。

### 5.4 .gitignore 默认策略

不配 ignore 的强制 git，遇到真实目录会直接不可用（10GB 视频目录 `git status` 要扫很久，`git add -A` 会炸）。

默认排除（与项目自带 `.gitignore` **合并**）：

```gitignore
# 依赖与构建产物
node_modules/  dist/  build/  target/  out/  .venv/  __pycache__/
# 缓存
.cache/  .gradle/  .m2/
# 大二进制
*.mp4 *.mov *.zip *.iso *.bin *.onnx *.pt *.safetensors *.gguf
# 日志
*.log
```

**大文件工作区的额外策略**：被 ignore 的数据不会进 worktree，若 Agent 真需要，按需从原目录复制一份进私有目录（回到「换空间」的思路）。

### 5.5 提交节奏

| 时机 | 谁触发 | 为什么 |
| --- | --- | --- |
| Assignment 开始 | host 强制 | 建立基线，可回滚到此 |
| Report 提交前 | host 强制 | 让「报告的内容」与「实际改动」能对上 |
| 中途检查点 | Agent 自定 | 长任务恢复点 |
| Ticket 结束 | host 强制 | 终态快照 |

不要「每写一个文件就 commit」：历史噪音、每次都要抢 `index.lock`、慢。

**并发提醒**：worktree 隔离了工作目录，**但没有隔离 `index` 和 `refs`**。两个 worker 同时提交到同一仓库会撞锁。解法是每个 Ticket 用自己的独立仓库（而不是共享主仓库的多个 worktree）——用磁盘换掉并发问题。

## 6. 与 dsh 契约的对接点

| dsh 契约 | 本设计如何用 |
| --- | --- |
| `FileSystem.resolve()` 产生稳定 `targetKey` | **必须做扎实**：realpath + 大小写折叠 + 长路径展开。否则「两条路径同一个文件」的前提破了，所有版本判定失效 |
| `write` / `editText` 的 `guard` 选填 | 在公共区域改为**必填**（D13） |
| `readBytes` 必须带 `maxBytes`，超限 `FS_TOO_LARGE` 而非截断 | 照抄，别自己实现一套 |
| `editText` 在一个临界区完成版本校验 + 字面量匹配 + 原子重写 | **直接复用**，不要自己实现 |
| `watch()` 观察失效 | 用于检测**用户/第三方**改动，投一条 Input 给 worker |
| `processPathFromHostPath` | 显式返回 `undefined`，堵住工作区外可读的洞 |

## 7. 剩余风险（诚实清单）

| 风险 | 现状 | 缓解 |
| --- | --- | --- |
| Windows 上 `workspace-write` 是 partial | 已知 | 文档明说；要强隔离就用独立 OS 账号 |
| Agent 与用户同时改同一文件 | 只能检测不能预防 | `watch()` + 写后校验 + 冲突交人 |
| 模型没注意到文件被改 | 接受（D17） | 日志提供发现渠道；必要时升到 R6 |
| 外部路径多文件写可能半完成 | 做不到原子 | 明确承诺只保证单文件；失败交人 |
| 强制 git 对大目录初始化慢 | 一次代价 | .gitignore 策略 + 后台初始化 |
