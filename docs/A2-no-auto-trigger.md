# 硬性约束：不做程序化触发

> 这份文件存在的唯一目的：**让这条要求不再被遗忘。**
> 它已经被我违反过一次（提议"索引时机改成每轮结束"），所以单独立档。

---

## 用户原话（三处，逐字）

1. > 「模型不知道有待办，**轮末就触发的太勤快了**，但是 user 记得，等到 super agent 实现后，应该由 router 来提醒，**这里先不需要自动触发**」
2. > 「**我说没说过，不要程序化触发索引**」

---

## 约束内容

**插件不得在任何事件上自动执行以下动作：**

| 禁止 | 举例 |
| --- | --- |
| 自动索引 | 不在 `agent/disposed`、不在每轮结束、不在定时器上跑 `indexSession` |
| 自动注入上下文 | 不在 `agent/pre-step` 里塞"你有个待办""可以搜历史"这类提示 |
| 自动发起封存 | 不在轮末自动调用 `memory_seal` |
| 自动提醒 | 不主动向会话投递任何消息 |

**唯一允许的触发方式：人或 CLI 显式发起。**

---

## 代码里怎么体现

`memory-plugin/src/dsh-bundle.ts`：

- **没有** `agent/disposed` 监听器（曾有过，已删除）
- **没有** `agent/pre-step` 监听器
- 只有一个 `session/event` 监听器，且它**只往内存 Map 写轮次号**，
  不索引、不注入、不发消息
- 索引入口 `ctx.provide('memory', {...})` 只暴露函数，自身不调用

---

## 为什么这条重要（不是形式主义）

9I 实验已经证明：**把东西放进视野 ≠ 模型会使用它**。
而自动触发是反方向的失败：**系统替模型做判断，猜错时没有任何信号**。

用户的方案是：**让 Router 层在 super-agent 实现后承担提醒职责**，
而不是让插件在底层偷偷注入。这是架构分工，不是实现细节。

## 检查方式（以后每次改完自查）

```bash
# 应当只输出一个 session/event 监听器，且不含 indexSession/applySeal/steer
grep -n "ctx.on(" memory-plugin/src/*.ts
```

**如果新增了任何 `ctx.on(...)`，必须说明它为什么不是「触发」。**
