**观察（相关性，非因果，务必按此理解）：**

- 三个主力 `deepseek-flash` 路由（account / official / siliconflow）的纠正频率高度一致：

- 唯一可较安全地说的是：`workbuddy/deepseek-v4.1-flash`（非 -sg）的纠正率 0.57/会话、

## 2. 长期偏好

每条标注证据强度。**「多次出现（强）」= 跨会话、跨项目复现；「仅一次（弱）」= 单点证据，不足以当规律。**

### 2.1 语言与表达

1. **中文优先，且反感"AI 八股"（多次出现（强））**
   全局 AGENTS.md 已固定"默认中文回复、代码注释中文、标识符英文"，实际会话中从未被推翻。
   更强的信号是对套话的厌恶：在 B 站人设项目里直接写明 *"不要八股、不要网络烂梗堆砌、不要『作为AI我……』式套话"*，
   并在评论区被吐槽后要求返工；另有 *"这个人设很有问题，你需要交叉验证，注意区分营销号、个性化人设、错误人设"*。
   → 他要的是**去 AI 味的自然表达**，不是"礼貌完整"。

2. **交付物形态必须匹配真实下游（多次出现（强））**
   同一份内容，输出格式由"谁来读"决定，且他会主动纠正：
   *"注意答案不要写成md样式的，就纯文本就行，老师不认识也不能渲染md"*（给老师看的）、
   实验报告要求宋体小四/行距 22 磅/去页眉注释（打印用）、
   Java 开卷考试资料明确"纸质 PDF 打印用"。
   → **默认不要上 Markdown 装饰，先问这份东西最终落到哪里。**

3. **不要额外加戏（多次出现（强））**
   *"不要自己加东西，比如实验1最简单的Java程序，和除了helloWorld另外输出的，以及说明"*、
   *"不对，别加页啊，我的意思是，把内容替换，不是说要代入进去"*、
   *"不要写成规则怪谈，不要加各种『错误巩固』，不需要各种免责声明，就正常写就行"*、
   *"不要加规则限制"*。
   → 他要**最小充分交付**：说写什么就只写什么，不主动补免责声明、不主动加章节、不主动扩范围。

### 2.2 干活方式

4. **先只读排查，确认后再动手（多次出现（强））**
   22 条/13 个会话明确要求只读或先别动，且措辞在升级：
   *"你先只读排查"* → *"不要改任何东西，先只查，手动交不会出现这个错误"* → *"不要动其他的容器，读也不行"* → *"你要干什么，别动别动容器"*。
   他甚至会把"只读"写进任务书的角色定义里：*"你是一个只读代码调查员"*、把"不要重写整个文件、不要改动其它内容"写进交付约束。
   → **默认动作顺序应是：只读 → 给结论 → 等他点头 → 才写。**

5. **不接受"猜"，要证据和实测（多次出现（强））**
   33 条/20 个会话出现"去查 / 别猜 / 你确定 / 实测 / 核实"。最典型的连续施压：
   *"记录下来，别老是猜"*、*"不对，你思考了吗就回答"*、*"不对，重新回顾所有上下文，重新说"*、*"不对吧，你再查一下呢"*。
   → 结论必须能指到证据（文件、命令输出、官方源码），"应该是/一般来说"会被直接打回。

6. **先规划再实现，方案要给他选（多次出现（强））**
   *"先别管github，先规划，不要开始写，先写README，和各模块的设计md"*、
   *"先分析呗，先别急着做"*、*"先规划，再开干"*、*"重新改一版，先给我看再改"*。
   全局 AGENTS.md 也固定了"多方案时列选项让我选，不要自作主张挑一个"。
   → **改代码前先给思路 + 选项，是硬性流程要求，不是客套。**

7. **一步一步讲，不许跳跃（多次出现（强））**
   *"你别跳跃，无头就是不用用户交互…你得一步一步说，要说为什么要重建，不要跳跃，作者根本不知道我们讨论的内容"*、
   *"你上来就有问题，返回clicked只需要解决假成功不就行了吗，认真思考"*。
   → 他会把结论直接拿去给上游作者看，所以**推理链必须自洽、可被第三方复现**。

8. **不要"每题出手一次"式的过度主动（多次出现（强））**
   *"不要再自己转述，你只需要等着所有问题解答完或者捕获中间异常，不要每个题出手一次"*、
   *"停停停，你这啥图片啊，不要自己造，去网上找现成的"*、
   *"先别等待，先汇报"*、*"待办就要往后放，先解决眼前的"*。
   → 他要**先汇报、后动手**，且不要为了显得勤快而频繁打断。

### 2.3 技术栈（全局 AGENTS.md + 会话双重印证）

9. **Python：PEP8 / Black / 行宽 88 / 3.11+ 显式类型 / pyproject+uv 或 poetry / pytest 覆盖率 80% / 用 `breakpoint()` 不用 `print`（强，AGENTS.md 固定，会话中无违例投诉）**

10. **C++：C++20 起 / `~/.clang-format` / CMake+Ninja / target 级 include / RAII + unique_ptr / 禁裸 new-delete、禁全局变量、禁 `using namespace std` / GoogleTest / O3（强，AGENTS.md 固定）**

11. **安全习惯：密钥/token 不进代码和注释、走环境变量或 .env + .gitignore、改认证/权限代码前先提示（强，AGENTS.md 固定）**

12. **提交信息用中文、小而聚焦（中，AGENTS.md 固定，会话中未单独复现）**

### 2.4 工具与协作

13. **子代理要"人设一致"、要控 token（多次出现（强））**
    *"你可以同时至多使用一位子代理…注意你的子代理需要人设一致"*、
    *"巡视一下评论区和私信，并开一个子代理去兑现day1的内容…（注意token用量，安全规则，防污染等）"*。
    → 委托时必须显式带上**人设继承 + 用量约束 + 防污染**三件事。

    → 顺序是：**先用官方/现成的 → 借鉴改造 → 最后才自造。**

## 5. 反复纠正的模式（最重要）

### 5.0 统计基线

- 233 个真人会话中，**42 个（18%）** 出现过明确的纠错语句；纠正占比中位数 **14.9%**。
- 纠正最密集的会话：`default-workspace` 的 132 轮会话里有 **12 次**纠正。
- 分型计数（基于 1,835 条对话式真人回复）：

| 纠正类型 | 次数 | 覆盖会话 |
| --- | ---: | ---: |
| 否定 / 判错（不对、错了、不是这样） | 55 | 24 |
| **需求指代错位（我说的是…、我不是这个意思）** | **29** | **13** |
| 没查就下结论（别猜、去查、你确定） | 33 | 20 |
| 动手越界（只读、别改、别动） | 22 | 13 |
| 加戏 / 多余产出 | 8 | 6 |
| 自作主张 | 4 | 3 |

下面每一条都给出**真实原话（已脱敏）+ 背后的真实诉求 + 应当被写进规则的执行动作**。

---

### 模式 1（最高频）：「我说的是 X」——**指代对象被换掉了**

他描述需求时经常用**指示性 + 对比性**表述（"侧边这个"、"本地"、"普通用户"、"那个模型"），
模型容易抓住一个自己顺手的相邻概念就开工，于是做完了才发现对象整个错了。

**原话证据：**
- *"我说的是侧边这个"* —— 在 `dsh-remote-access-cidr` 的**同一个项目里重复出现 3 次**（跨不同会话）。
- *"我说的是本地"* → 紧接着 *"不是让你改本地"* —— 同一件事，前后两轮才说清。
- *"我说的是普通用户，不是普通 sudo 用户"*。
- *"我说的是学习通这个服务器的启停，你给我弄哪去了"*。
- *"我说的是打开 wallpaper engine 插件就是正常的，不是说重新打开是正常的"* —— 连"什么叫复现"的定义都错位。
- *"我说的是模型的思考强度"* / *"我说的是聊天那个模型，不是说你"* —— 把人/模型/参数的指代搞混。
- *"我说的是本机的 ~/projects"*。
- *"我让你借鉴他的操作，不是让你直接用"*。
- *"我说的是 DeepSeek 那两个工具，不是现造"*。
- *"你理解错了，无头不是自托管"* —— 术语定义直接错。
- 最激烈的一次反问：*"你什么意思，什么叫我理解错了，是你理解错了"* —— 模型把自己的误解说成用户的误解，引发强烈反弹。

**真实诉求：** 他要的不是"更聪明地猜"，而是**在动手前把指代对象复述一遍并确认**。
他自己也在用对比消歧（"不是…是…"），说明他认为"先说清对象"是对话双方的义务。

**这条为什么最值钱：** 它是 29 次/13 个会话里的头号原因，而且**每一次都发生在真正动手之后**
——成本不在沟通，在返工。

**执行动作：**
> 收到含**指示代词或泛指名词**（这个/那个/侧边/本地/远程/模型/工具/接口/用户）的需求时，
> **先复述成具体对象再动手**："你指的是 A（路径/URL/进程/参数），不是 B，对吗？"
> 若一句话里有 ≥2 个候选对象，必须列出候选让他选，不许自己挑。

---

### 模式 2：「别老是猜」——**没查就下结论**

**原话证据：**
- *"我说的是每个 agent 操作自己的侧栏，只剩托盘时全部不可用，记录下来，别老是猜"*。注意"记录下来"——
  他要的不只是这次答对，是**结论要落盘成持久事实**，避免下次再猜一遍。
- *"不对，你思考了吗就回答"*。
- *"不对，重新回顾所有上下文，重新说"*。
- *"不对吧，你再查一下呢"*。
- *"你上来就有问题，返回 clicked 只需要解决假成功不就行了吗，认真思考"*。
- *"先给我去查，后台会话没在使用的浏览器，是占着资源还是没占着"* —— 这是可测事实，不该给推测。
- *"查查为什么没提交却交不了，他就不可能和官方传的一模一样还有问题"*。
- *"本机和路由器的规则并不一致"* —— 模型把两个对象当成一个。

**真实诉求：** 他要**可验证的事实**，尤其是"资源到底占没占"、"接口到底存不存在"这种一句话就能测的东西。
推测在这些场合是**负资产**，因为它会污染后续所有推理。

**执行动作：**
> 凡是"是否存在 / 是否占用 / 是否生效 / 是不是官方提供"这类**可测量**的问题，**先跑命令或读源码再回答**，
> 禁止用"一般来说/通常/应该是"。拿不到证据就直说"查不到，需要你提供 X"。
> 一旦查实，**写进项目文档或 AGENTS 类记忆**，不要下次重查。

---

### 模式 3：「不要改任何东西，先只查」——**动手越界**

用户对**生产环境和他人容器**的改动极度敏感，措辞会一路升级到情绪化。

**原话证据（按强度递增）：**
- *"你先只读排查"*
- *"先别用浏览器"*
- *"不要改任何东西，先只查，手动交不会出现这个错误"*
- *"不要动其他的容器，读也不行，继续尝试和服务器交互"* —— **连读都不行**
- *"你要干什么，别动别动容器"* —— 口吃式重复，是紧急制止
- *"你有毛病是不是，给我改回去，不要动全局配置，继续找接口"* —— **要求回滚**

另有一类隐形越界：**在协作场景里自己改掉了本该留给上游作者的东西**
—— *"先归档，我们只提 issue 不给他改代码"*、*"把一里面的实测去掉…这个留给作者"*。

**真实诉求：** 排查与修复是**两个阶段**，中间必须有一次他的授权。尤其是：
共享容器、全局配置、别人的仓库、正在跑的任务 —— 这四类**读可以谈、写一律不行**。

**执行动作：**
> 进入排查任务时**默认只读**。任何写操作（改文件、改配置、重启/删除容器、推代码）前，
> 必须先输出"我打算改 X，影响范围 Y，怎么回滚 Z"并**等他明确同意**。
> 需要改动他人仓库时，只在本地 fork 做，产出 PR/issue 建议，**不碰原仓库**。

---

### 模式 4：**加戏**——交付物比要求的多

**原话证据：**
- *"不要自己加东西，比如实验 1 最简单的 Java 程序，和除了 helloWorld 另外输出的，以及说明"*。
- *"不对，别加页啊，我的意思是，把内容替换，不是说要代入进去"*。
- *"工具调用放到系统提示词后，紧接着，人设太细太碎，很多东西都没用，不要写成规则怪谈，不要加各种『错误巩固』，不需要各种免责声明，就正常写就行"*
  —— 这条信息量最大：他反感的是**"防御性写作"**（免责声明、错误巩固、规则堆砌）。
- *"不要加规则限制"*（在做人设提示词时）。
- *"我让你用交互式操作，没让你真用键鼠交互"*。

**真实诉求：** 额外内容在他这里不是"加分"，是**噪音和返工**。他改起来还要先删掉。

**执行动作：**
> 交付严格等于清单。**不主动**加免责声明、不加"进一步建议"章节、不扩写未被要求的条目、
> 不为了显得完整而补充边界情况。想要补充，就在末尾用**一行**问"要不要顺带加 X？"，不直接写进正文。

---

### 模式 5：**同一问题被"修"了多次仍未修好**——假修复

**原话证据：**
- *"不行，还是不对，你重新写这部分脚本吧，不要让之前的残留影响你"* —— 他要求**推翻重写而非打补丁**，
  因为连续打补丁会让上下文里的错误假设一直延续。
- *"不对，还是没有连接，他会在连接中那里一直转圈"* —— 给了具体的失败形态，是模型没复现到该形态。
- *"还是没有横线"* / *"还是没有配音啊"*。
- *"反复重建确实是个问题"*、*"改明度不对，是改色彩"* ×4 连击（DS-API 配色需求）：
  *"都不对，是选的颜色，不是深度"* → *"都不对，是换个浅色调，不是直接换个颜色"* → *"要渐变啊，你在做什么，是让你把深色浅化，不是让你淡化"* → *"我说的是蓝紫渐变！而且你这全部都太深了"* → *"不是让你换大类，你就找个浅色的蓝和紫这么费劲吗"*。
- *"普通筛选正常，只是你新增的有问题"* —— 提示了"责任边界"，模型该据此缩小排查面。

**真实诉求：** 他每次反馈都给了**可判定的失败现象**（没横线、没配音、一直转圈、颜色太深）。
他要的是：**先复现这个现象，再定位，再改，改完自己验证一遍这个现象消失了**。
而不是"我按你说的改了参数，应该好了"。

**执行动作：**
> 用户报告"还是不行"时，**禁止在同一假设上继续微调**。必须先：①复现或明确复现不了；
> ②列出当前假设及其可观测判别式；③若连续 2 次失败，**推翻重来**（新建最小实现，不复用此前的残留思路）。
> 改完必须自己验证**用户描述的那个具体现象**，报告"现象消失/仍在"。

### 模式 6：**过度主动打断**——插手节奏

**原话证据：**
- *"不要再自己转述，你只需要等着所有问题解答完或者捕获中间异常，不要每个题出手一次"*。
- *"停停停，你这啥图片啊"*、*"你快先别推了，先把这个问题修好行不行"*。
- *"不要再给我提这个自托管载体了，你告诉我为什么这两个不能解决"* —— 反复推销同一方案。
- *"别再提这两件事，赶紧测"*。
- *"待办就要往后放，先解决眼前的"*。

**真实诉求：** 他要**控制节奏**。主动汇报是好的，主动开新战线是坏的。
已经被否决的方案不许再提；现状是"正在跑一个长任务"时，不要中途插入别的工作。

**执行动作：**
> 不重复提被否决过的方案（记进记忆）。长任务进行中**只报状态、不另起话题**。
> 待办事项排在当前问题之后，不主动插入。

### 7.2 结论：三类各自的解法完全不同

**① 没听懂意图 —— 最主要，但不是"笨"，是"需求里混着让步与约束"**

用户提需求时习惯把**目标、约束、可接受让步**写在同一段话里，例如：
> "2-3 条结合起来，**可以允许部分能力退化**"

这里的"可以允许退化"是**让步**，不是**目标**。模型把它当目标 → 做出了"主动降级"的方案 → 全盘跑偏。
同理 `c8dfb160` 里"打开插件就正常"是**判据**，不是**动作**。

**解法：** 不是"更努力地理解"，而是**强制复述**。
用户自己给出了这个解法的原型：「**你给我复述一遍来**」「**你完整重读一遍历史，给我重新说**」。
→ 需求里出现"可以/允许/至少/尽量/最好"这类**弹性词**，或出现"就是/才/即"这类**判据词**时，
必须先输出"我理解目标=…，约束=…，可接受让步=…，验收判据=…"四段，再动手。

**② 自作主张扩大范围 —— 本条最危险，且几乎总是①的后果**

`9d492565` 的"替换 vs 加页"表面看是范围失控，但根因是**没确认"替换"这个动词的作用对象**。
一旦确认了作用对象，"加页"这种越界根本不会发生。

**解法：** 交付前做一次**动作-对象配对检查**：用户说的动词（替换/补充/修改/删除/生成）作用于哪个对象？
把这个配对写出来。**动词错配比对象错配更隐蔽**，因为输出看起来"做完了"。

**③ 忘了先前约束 —— 数量最少，但后果最严重**

只有 3 个会话出现，但每一条都是**硬性的、被明确重复过的指令**：
"丢弃第一次结果"、"禁止开思考"、"你曾经成功过"。
其中 `fb985b49` 重复了 6 次仍被违反，`120809f4` 甚至**否认了自己做过的事**。

**解法：** 这类不能靠"记得更牢"，只能靠**外部化**：
把会话中出现的硬约束（禁止/必须/一律/不要）**在首次出现时立刻写成一个可勾选的清单**，
每次动手前对照清单自检。这正是用户反复说"**记录下来**"的真实含义 ——
他要的不是模型记性好，是**把约束落到上下文之外的载体上**。

### 7.3 一句话

> **不是"没听懂"，是不区分"目标"与"让步"；不是"忘性大"，是没有把硬约束外部化；
> 不是"爱加戏"，是没做动词-对象配对。**
